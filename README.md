# LingoGrab

> 把读过的东西，变成记得住的东西。

**在线 Demo** 👉 https://lingograb.getyuli.com/

这是一个以职场人持续学习为核心、兼顾日常与旅行场景的英法语言学习 MVP（数据为演示用）。它把「结构化课程 → 情境填空 → 错题解析 → 个人拾取 → 间隔复习」做成一条可以持续体验的闭环。

---

## 一句话

**把工作和阅读中遇见的英语、法语，变成今天能学、以后能用的个人语言课。**

## 当前 Demo 已包含

- 首次打开先选择英语 / 法语，再进入对应级别书架；
- 两步新手引导：先选语言，再直接练 3 道题或从示例材料完成一次拾取；
- 真实的今日学习面板：连续天数、待练数量、完成进度和下次复习日期都来自本机学习记录；
- 书架式「全部词库」：法语提供日常 A1、旅行 A1–A2、职场 A2–B1，英语拆为职场 B1 / B2；
- 词书预览只保留一个「开始学习」动作，内容词预览不展示代词、冠词和字幕专名噪声；
- FrequencyWords / OpenSubtitles 2018 英法高频词数据底座，每种语言清洗取前 5,000 词；
- 系统词库 / 我的拾取分区与语言筛选；
- Lingvist 式情境填空、答案判断与错题解析；答错后必须重新输入正确答案才能进入下一词；
- 区分「目标答案」「可接受表达」与「真正错误」，避免把 explain / agree 等自然表达误判为错误；
- 答错后先由本地规则判断错误类型：明显拼写或重音问题不自动调用模型，相似真实词或复杂题目会在展示核心用法的同时自动生成 AI 深度讲解；每题也始终保留主动调用入口；
- 智谱 GLM-4.7-Flash / GLM-4-Flash-250414 的按需智能选词与错题再解释（通过服务端代理，前端不暴露 API Key）；
- 法语动词 / 时态速查；
- 文本导入后的 AI / 本地双路径表达识别，可一键加入并立刻开始练习；个人拾取会进入同一复习队列；
- 每轮学习结束后展示完成数、首次答对率与重输巩固数，并按表现安排 1 / 3 / 7 / 14 / 30 / 60 天复习；
- 邮箱账号、游客模式与多设备云同步；本地进度、掌握词、错题和个人词库在离线时仍可使用；
- 学习记忆面板：只保存当前词书、掌握卡、错题与个人拾取，并作为 AI 个性化的最小上下文；
- 可编辑每日目标、AI 个性化开关、学习数据导出、重置和真实入库的问题反馈表单；
- canonical、robots.txt、sitemap.xml、Open Graph 与 WebApplication JSON-LD 等 SEO 基础；
- 桌面端固定左侧导航、移动端固定底部导航的响应式布局。

## 三轮驱动

1. **结构化词库**：没有素材也能直接学，保证课程骨架与难度梯度。
2. **AI 推荐 / 精选**：根据岗位、水平、错题和已掌握词，控制“刚好够难”。
3. **个人导入**：文章、会议纪要与工作表达进入个人语言资产。

## 学习闭环

1. 选词库或导入真实材料。
2. 系统筛出值得学习的词与搭配。
3. 在情境句中主动回忆，不孤立背词义。
4. 答错后解释“为什么”，英语讲搭配，法语讲变位和时态。
5. 把掌握度写回个人模型，决定下一次出现时间。

## AI 接入与数据边界

完整的职责、缓存、内容生产与成本控制设计见 [`资料/AI与代码分层方案.md`](资料/AI与代码分层方案.md)。

- **当前模型**：通过独立 EdgeOne Function 优先调用智谱 `glm-4.7-flash`，用于导入材料选词与“AI 换个讲法”；失败时降级到 `glm-4-flash-250414`。两级都限定为官方当前标注免费的模型，不会自动切换到付费模型；两级都失败时回退到本地规则。
- **访问方式**：访客无需注册第三方模型账号，API Key 只存在于服务端环境变量中。
- **可靠性**：词书、答题、核心用法和本地选词不依赖 AI；AI 未加载、用户取消授权或免费模型不可用时自动回退。
- **正确性边界**：法语人称、变位和时态以词书内的已校验数据为事实源；错题反馈由确定性规则生成，不允许模型覆盖语法事实。英语材料筛选与“AI 补充解释”才调用模型。
- **隐私**：只有用户主动点击 AI 按钮时才会发送文本。演示明确提示不要上传公司机密、个人信息或其他敏感材料。
- **学习记忆**：AI 只接收经过裁剪的学习摘要（当前词书、已掌握数量、少量错题和拾取词），服务端再次限制字段、数量与长度，不发送账号密码或整段历史材料。
- **生产迁移**：当前 MVP 暂时使用兼容路由 `/api/pickup`；正式产品应迁移至 LingoGrab 自己的 EdgeOne 项目与独立 Key，以分离两个产品的额度和日志。

## 专项评测（2026-09-29）

本仓库已经建立可复跑的 LingoGrab 专项评测，不再用“7 项自动化测试”代替 AI 教学质量。当前评测集共 52 条合成样本：35 条错误分流、12 条英法错因讲解、5 条语料精选。

- 错误类型分流准确率：35/35；自动调用 AI 决策准确率：35/35。
- 线上接口可用率：17/17；AI 讲解固定规则通过 11/12，产品负责人逐例复核 12/12。
- 语料精选在格式、相关性、原文溯源与显式隐私字段保护上通过 5/5。
- 响应时延中位数 2.643 秒，P95 18.036 秒；13 次模型请求均由 `glm-4-flash-250414` 降级路由完成，说明 `glm-4.7-flash` 在本轮环境中没有形成可用响应，仍需继续治理主模型可用性和长尾延迟。

完整考题、原始模型输出、逐例判定与口径边界见 [`eval/`](eval/README.md) 和 [`最终评测报告`](eval/reports/lingograb-eval-2026-09-29.md)。这是作品集阶段的小样本离线专项评测，不等于真实用户学习效果或专家盲评。

产品闭环另有一套可复跑评测：覆盖多答案公平性、复习排期、首次体验、个人拾取进入练习、完成页、移动端横向溢出和运行时错误。当前共 36 项检查全部通过，详见 [`产品优化评测报告`](eval/reports/lingograb-product-optimization-evaluation.md)。该结果只证明实现与关键旅程符合预期，不能替代留存、长期记忆效果、语言专家审校或真实设备测试。

## 账号与多设备同步

- 游客不注册也能完整学习，数据保存在浏览器。
- 登录后通过 EdgeOne Functions 调用 Supabase Auth 和 `user_sync`，LingoGrab 继续使用兼容键 `pickup_state_v1`，避免老用户学习数据丢失。
- 首次登录会合并本机与云端的掌握卡、错题、个人拾取和各词书进度；数组做并集、进度取较大值、偏好取更新时间较新的版本。
- 云端使用版本号做条件写入；发生并发冲突时重新拉取再合并，避免手机和电脑互相静默覆盖。
- AI Key 与数据库 service role 都留在服务端，前端只保存用户 access / refresh token。

## 开源词库数据

- 原始数据：[hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords)，英法文件各 50,000 行；内容许可为 CC BY-SA 4.0。
- Demo 在浏览器端去除明显非单词 token 与重复项，分别取前 5,000 个有效英法词作为词库索引，再按频次区间拆成两个学习梯度。
- 高频区间不是官方 CEFR 分级。A1 / A2、B1 / B2 是 MVP 的产品学习梯度；页面明确区分「本级词量」与「已经人工校验、可直接答题的学习卡」，避免把原始词表伪装成完整课程。
- 原始文件与使用说明位于 [`data/`](data/README.md)。

## Origin Story（怎么想出来的）

我在一家跨境电商公司做出海产品经理，一直在提升英语。我先给自己搭了一个「双语库」——不是背单词，而是让 AI **自动从我每天真实接触的英文内容里**，把值得记的词和表达「拾」出来，配上原句情境和出处，重点标黄，定期复习，越用越懂我。

用了一阵我意识到：**「从你真实接触的内容里，自动拾取值得记住的东西 + 带情境溯源 + 间隔复习」这套机制，不该只属于英语、只属于我——每个爱学习的人都需要。** 于是把「自动采集」换成「用户主动投喂」，把「英语」扩展成「任何值得记住的内容」，就有了 **LingoGrab**。
